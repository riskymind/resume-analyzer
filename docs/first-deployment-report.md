# First Controlled Deployment — Private Preview Report

_Date: 2026-11-11 · Branch: `deploy/private-preview` · Deployed commit: `f21fe83` · PR: #6 (draft, not merged)_

**Outcome.** The private preview runs end to end: Vercel serves the frontend and proxies `/api/*` to the
Render backend, which uses a Render PostgreSQL database. Everything is behind Vercel Authentication, the
backend refuses any request that did not come through the proxy, and live Gemini calls are switched off.
Phases A–E of the deployment plan are complete. Phase F (live Gemini) and Phase G (operational readiness)
have not started.

> **No real-user launch has occurred.** No real resumes were used, registration is not public, PR #6 is not
> merged, and no live Gemini call has been made (`AI_CALLS_ENABLED=false`).

## 4. AI kill switch

Production mode requires `GEMINI_API_KEY`, and resume upload and job creation call Gemini immediately, so a
configured key would have meant live calls during smoke testing. `AI_CALLS_ENABLED` (default `true`) was added:
when `false`, no AI client is built (generation and embeddings), AI routes return 503 `ai_not_configured`, and
readiness reports `ai_provider: "disabled"` with 200. Covered by three new tests. `render.yaml` sets it to
`false`; re-syncing the Blueprint resets it to `false`.

Known cosmetic inconsistency: the startup log line says `ai_provider: not_configured` where readiness says
`disabled`. Left unchanged during deployment.

## 5. Phase D: Vercel frontend

The project was created without a Git connection, and the stable domain was claimed before the Render sync
so `CORS_ORIGINS` never needed a placeholder. Protection was raised from `all_except_custom_domains` to
`all` before the first deployment. The first deployment had **no** backend variables, so privacy could be
proven before anything could reach the backend.

Run by the owner in a Vercel-authenticated browser; verified from Render request logs.

Not verifiable from tooling: row counts after deletion (the database correctly refuses external

**Not exercised (needs Phase F):** structured extraction, quality scoring, job matching, rewriting,
accepting or rejecting suggestions, protected-fact verification, PDF/DOCX exports, the five templates, and
rewrite deep links with real data. These are covered by automated tests with a mocked AI provider, which is
**not** live Gemini verification.

## 7. Gemini verification status

**Not started.** The key is stored on Render; `AI_CALLS_ENABLED=false`; zero live calls made. Phase F needs
separate authorization with a call limit, and is enabled by setting `AI_CALLS_ENABLED=true` on the Render
service (dashboard → Environment → save and deploy).

## 9. Verdict

The private preview is **suitable for continued private testing** with fictional data. The security
boundaries held in every check: Vercel Authentication on every hostname, the backend access key cannot be
bypassed, secrets stay server-side, and AI usage is off. It is **not** suitable for real users until Phase F
(live Gemini) and Phase G (paid plans, backups, monitoring) are complete and separately approved.
